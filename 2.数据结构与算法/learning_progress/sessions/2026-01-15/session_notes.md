**日期**: 2026年1月15日
**题目**: LeetCode 560 - 和为 K 的子数组 (Subarray Sum Equals K)
**难度**: Medium
**标签**: 前缀和, 哈希表, 数组

---

## 核心知识点

### 前缀和 + 哈希表

**核心思想**：
1. 用前缀和快速计算区间和：`sum[i, j] = prefix[j+1] - prefix[i]`
2. 用哈希表记录每个前缀和出现的次数：`{前缀和值: 出现次数}`
3. 通过查找哈希表，快速判断是否存在满足条件的目标

**数学推导**：
```
要求: sum[i, j] = K
即: prefix[j+1] - prefix[i] = K
变形: prefix[i] = prefix[j+1] - K
```

因此，当遍历到位置 `j` 时，只需要查找哈希表中 `currentSum - K` 的出现次数。

---

## 关键理解点

### 1. 为什么 countMap 初始化为 {0: 1}？

**原因**：处理从索引 0 开始的子数组。

`{0: 1}` 代表 `prefix[0] = 0` 这个**空前缀**存在且出现 1 次。

**举例**：
- `nums = [3, ...]`, `K = 3`
- 子数组 `[3]` 从索引 0 开始
- `currentSum = 3`, `target = 3 - 3 = 0`
- `countMap[0] = 1`，所以找到了 1 个子数组

### 2. 为什么记录"次数"而不仅仅是"存在"？

因为可能有**多个不同位置**的前缀和值相同，每个位置都代表一个满足条件的子数组起点。

**举例**：`nums = [2, -2, 2, -2, 2]`
```
prefix: [0, 2, 0, 2, 0, 2]
```
- 前缀和 `0` 出现了 3 次（索引 0, 2, 4）
- 当 `target = 0` 时，有 3 个子数组满足条件

### 3. 顺序：先查询再更新

**必须先查询** `countMap[target]`，**再更新** `countMap[currentSum]`。

**原因**：我们要找的子数组是 `nums[i..j]`，其中 `i < j`（i 必须在 j 之前）。

如果先更新，可能会把当前位置自己也算进去，导致重复计数。

## 暴力解法 vs 优化解法

### 暴力解法
```python
for i in range(len(nums)):
    current_sum = 0
    for j in range(i, len(nums)):
        current_sum += nums[j]
        if current_sum == k:
            result += 1
```
- 时间复杂度: O(n²)
- 空间复杂度: O(1)

### 优化解法（前缀和 + 哈希表）
```python
import collections
from typing import List

class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        countMap = collections.defaultdict(int)
        countMap[0] = 1
        result = 0
        currentSum = 0

        for num in nums:
            currentSum += num
            result += countMap[currentSum - k]
            countMap[currentSum] += 1

        return result
```
- 时间复杂度: O(n)
- 空间复杂度: O(n)

## 算法流程详解

以 `nums = [1, -1, 1, -1]`, `K = 0` 为例：

```
索引:     0   1   2   3   4
nums:         1  -1   1  -1
prefix:   0   1   0   1   0
```

| j | currentSum | target | countMap[target] | result | 找到的子数组 |
|:-:|:----------:|:------:|:----------------:|:------:|:---|
| - | 0 | - | - | 0 | - |
| 0 | 1 | 1 | 0 | 0 | - |
| 1 | 0 | 0 | 1 | 1 | [1, -1] |
| 2 | 1 | 1 | 1 | 2 | [-1, 1] |
| 3 | 0 | 0 | 2 | 4 | [1, -1, 1, -1], [1, -1] |

**最终结果**: 4 个子数组的和为 0

## 问答环节记录

### 用户提出的关键问题

1. **前缀和的作用**：主要用于解决"和为 K 的子数组数量"、"连续元素和为特定值"等问题，核心优势是将区间和查询从 O(N) 降到 O(1)。

2. **是否只能处理连续区间**：是的，前缀和只能处理**连续子数组**（Subarray）问题。如果区间不连续（子序列 Subsequence），需要用动态规划或回溯。

3. **currentSum 的计算**：通过遍历时的 `currentSum += nums[j]` 累加得到，自然而然就是 `prefix[j+1]` 的值。

4. **如何通过次数知道具体位置**：不需要知道具体位置！题目只要求统计数量，`countMap[target]` 的值就是满足条件的子数组数量。

5. **会不会多计算**：不会。`countMap[0] = 2` 表示之前有 2 个位置的前缀和为 0，每个位置都是一个有效的子数组起点，应该全部统计。
