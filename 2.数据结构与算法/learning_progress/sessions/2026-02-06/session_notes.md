## 知识点回顾：哈希冲突（复习）

### 哈希冲突产生原因
- 鸽巢原理：输入空间 > 输出空间，冲突不可避免
- 哈希函数底层求模，不同元素可能得到相同结果

### 两种解决方法

| 方法 | 优点 | 缺点 |
|:-----|:-----|:-----|
| 链地址法 | 冲突隔离，查找稳定 | 需要额外指针空间 |
| 开放寻址法 | 缓存友好，内存效率高 | 聚集现象，高负载时性能下降 |

### 开放寻址法的三种状态

| 状态 | 查找行为 | 插入行为 |
|:-----|:---------|:---------|
| EMPTY | 停止，未找到 | 可以插入 |
| OCCUPIED | 匹配返回/不匹配继续 | 冲突，继续探测 |
| DELETED | **继续查找**（关键） | 可以插入，复用位置 |

### 负载因子
- 0.75 是黄金平衡点：权衡时间与空间效率
- Python dict 在 0.66 时扩容（更保守）

## 知识点：链表基础

### 链表 vs 数组

| 特性 | 数组 | 链表 |
|:-----|:-----|:-----|
| 内存布局 | 连续 | 非连续 |
| 随机访问 | O(1) | O(n) |
| 插入/删除 | O(n) | O(1) *已找到位置 |
| 空间开销 | 仅数据 | 数据+指针 |

### 链表核心概念
- **head**：链表入口，空链表 `head = None`
- **tail**：`next` 为 `None` 的节点
- **节点结构**：`val` (值) + `next` (指针)

### 真实应用
- LRU 缓存淘汰
- Kafka 消息队列
- 操作系统内存管理
- 区块链结构

## LeetCode 206：反转链表

### 三指针迭代法

**核心变量**：
- `prev`：已反转部分的头（初始 `None`）
- `curr`：当前处理的节点（初始 `head`）
- `temp`：保存下一个节点，防止断开丢失

**四步反转**：
1. `temp = curr.next` - 保存下一个
2. `curr.next = prev` - 反转指针
3. `prev = curr` - prev 前进
4. `curr = temp` - curr 前进

**返回**：`prev`（新的头节点）

### 最终代码

```python
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        prev, curr = None, head

        while curr:
            temp = curr.next
            curr.next = prev
            prev = curr
            curr = temp

        return prev
```

### 复杂度
- 时间：O(n)
- 空间：O(1)
