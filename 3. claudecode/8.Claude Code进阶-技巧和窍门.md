这是一份关于优化 **MCP (Model Context Protocol)** 使用效率的笔记整理。核心思路是通过 **CLI (命令行工具) + 自定义指令** 来替代部分重型 MCP，从而节省 Context Window（上下文窗口）和 Token 消耗。

------

## 笔记：通过 CLI 替代方案优化 MCP 使用

### 核心观点

部分 MCP（如版本控制、数据库、部署工具）本质上是对现有强大 CLI 的封装。虽然使用方便，但会占用宝贵的 Context Window。

**优化策略**：将 MCP 的功能剥离，转化为直接调用 CLI 的 **Skills (技能)** 或 **Commands (指令)**。

### 1. 为什么要这样做？ (The "Why")

- **节省 Context Window**：MCP 加载时会占用上下文空间。将其替换为按需调用的 CLI 指令，可以让上下文专注于实际工作内容。
- **降低 Token 消耗与成本**：即使有了“懒加载”优化，MCP 操作（特别是重型操作如数据库查询）在上下文内运行仍消耗大量 Token。通过 CLI 运行操作可以显著降低 Token 使用量。

### 2. 操作方法：CLI + Skills 模式

不要一直加载整个 MCP，而是创建特定的指令来通过 CLI 执行常用任务。

- **原理**：利用工具原本的 CLI（命令行界面），将其封装进自定义的 Skills 或 Commands 中。
- **效果**：功能相同，便利性相近，但资源占用大幅降低。

#### 示例

| **工具类型** | **传统 MCP 方式**            | **优化后的 CLI/Skill 方式**                                  |
| ------------ | ---------------------------- | ------------------------------------------------------------ |
| **GitHub**   | 全程加载 GitHub MCP          | 创建 `/gh-pr` 指令，底层直接调用 `gh pr create` 并附带预设参数。 |
| **Supabase** | 使用 Supabase MCP 占用上下文 | 创建直接调用 Supabase CLI 的 Skills。                        |

### 3. 关于“懒加载 (Lazy Loading)”的更新说明

- **现状**：Claude Code 团队（提及 Boris）近期在大海捞针（Memory Management）方面取得了进展，引入了 MCP 的 **懒加载** 功能。
  - *改进点*：MCP 不再从一开始就吃掉上下文窗口，Context Window 的问题基本得到解决。
- **局限性**：懒加载**无法解决 Token 使用量和成本问题**。
- **结论**：**CLI + Skills** 的方法仍然是目前最优的 **Token 优化方案**。对于重型操作（如数据库查询、部署），直接在 CLI 运行比在 Context 中通过 MCP 运行更经济、更高效。

------

### 总结

- **轻量级/高频交互** $\rightarrow$ 可使用 MCP（配合懒加载）。
- **重型操作/成本敏感** $\rightarrow$ 使用 **CLI + Skills** 封装，作为“伪 MCP (Pseudo-MCP)”运行。
