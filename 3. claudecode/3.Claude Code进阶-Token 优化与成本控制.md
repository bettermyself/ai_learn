## 1. 核心策略：子智能体架构 (Subagent Architecture)

最主要的优化手段是**人岗匹配**——根据任务难度委派给最便宜但够用的模型。

| **任务类型**     | **推荐模型** | **理由**                         |
| ---------------- | ------------ | -------------------------------- |
| **探索/搜索**    | Haiku        | 快速、便宜，足以胜任文件查找任务 |
| **简单编辑**     | Haiku        | 针对单文件修改且指令明确的任务   |
| **多文件实现**   | Sonnet       | 编程任务的最佳平衡点             |
| **复杂架构**     | Opus         | 需要深度推理能力                 |
| **PR 审查**      | Sonnet       | 能够理解上下文并捕捉细微差别     |
| **安全分析**     | Opus         | 无法承担遗漏漏洞的风险           |
| **撰写文档**     | Haiku        | 结构简单                         |
| **调试复杂 Bug** | Opus         | 需要对整个系统有全局把握         |

> 90% 的编码任务默认使用 Sonnet。如果首次尝试失败、任务涉及 5 个以上文件、涉及架构决策或安全关键代码，则升级到 Opus。



### 💡 成本效益分析 (Cost Analysis)

> **观点：** 仅仅从 Opus 降级到 Sonnet 4.5 虽然绝对值上节省了 ~66.7%，但 **Haiku + Opus 的组合拳** 性价比最高。
>
> - **Haiku vs Opus:** 成本差异达 **5倍**。
> - **Sonnet vs Opus:** 成本差异仅约 **1.67倍**。



### 实施方法

在定义 Agent 时直接指定模型（YAML 示例）：

```yaml
name: quick-search
description: Fast file search
tools: Glob, Grep
model: haiku # Cheap and fast
```



## 3. 工具与流程优化 (Tool & Workflow Optimization)

优化 Claude 调用的工具和运行环境，直接减少 Input/Output Token。

### 🛠️ 工具层优化

- **替换 grep:** 使用 **`mgrep`** 替代默认的 `grep` 或 `ripgrep`。
  - *效果：* 平均减少约 **50%** 的 Token 消耗（通过更紧凑的输出格式）。
- **后台进程管理:**
  - 不要让 Claude 实时流式读取所有终端输出。
  - **技巧:** 使用 **`tmux`** 在后台运行耗时进程。
  - *操作：* 仅复制/总结必要的终端输出给 Claude，避免为了看进度条浪费昂贵的 Output Token ($25/M)。



### 🧩 系统提示词瘦身 (Advanced)

- *风险较高，适合极客*
- Claude Code 的默认 System Prompt 占用约 **18k tokens** (9% 上下文)。
- 可以使用补丁（如 `YK's system-prompt-patches`）将其缩减至 **~10k tokens**。
- *收益：* 每次对话节省 ~7,300 tokens (静态开销减少 41%)。



## 4. 代码库架构对 Token 的影响 (Codebase Architecture)

**代码结构直接决定 Token 账单。** 臃肿的文件会导致 Claude 反复读取、多次调用工具翻页，甚至在中间丢失上下文。

### ✅ 推荐架构：模块化 (Modular Codebase)

将数千行的大文件拆解为数百行的小文件。

- **优点：** 减少 Token 读取量、提高一次性成功率、降低“重新读取”产生的额外费用。

- **结构示例：**

  ```Plaintext
  root/
  ├── src/
  │   ├── modules/            # 系统核心
  │   │   ├── ordering/       # 独立的 "订单" 模块
  │   │   │   ├── api/        # 公共接口
  │   │   │   ├── domain/     # 纯业务逻辑
  │   │   │   └── use-cases/  # 编排逻辑
  │   │   └── identity/       # 独立的 "认证" 模块
  │   ├── shared/             # 共享内核 (Kernel, Events, Utils)
  │   └── main.ts             # 极简入口
  └── tests/                  # 全局测试
  ```

### 🧹 保持精益 (Lean Codebase)

- **定期清理:** 死代码 (Dead Code) 也是要花钱读的。定期使用工具识别并删除。
- **人工+AI 重构:** 人工浏览代码库寻找重复模式 -> 提取上下文 -> 喂给 Claude 进行针对性重构 (Refactor Skill)。
