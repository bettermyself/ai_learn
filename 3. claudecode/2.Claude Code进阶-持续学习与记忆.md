## 1. 核心理念：为什么需要持续记忆？

### 🔴 痛点 (The Problem)

- **资源浪费**：重复修正相同的错误会导致 token、上下文窗口和时间的浪费。
- **情绪成本**：当 AI 重犯已经纠正过的问题时，用户体验极差（"Cortisol spikes"）。
- **手动重复**：通常需要通过再次提示（Re-steering）来校准 Claude 的方向。

### 🟢 解决方案 (The Solution)

- **自动沉淀**：当 Claude 发现非同寻常的信息（如调试技巧、变通方案、项目特定模式）时，将其保存为一项新 **Skill**。
- **自动调用**：下次遇到类似问题时，自动加载该 Skill，无需重复教导。



## 2. 实现方案：[**Continuous Learning Skill** ](https://github.com/affaan-m/everything-claude-code/tree/main/skills/continuous-learning)

该方案通过 **Hook（钩子）** 机制，在会话结束时自动评估并提取有价值的知识。

### ⚙️ 核心机制：Stop Hook vs UserPromptSubmit

- **选择 Stop Hook (推荐)**：
  - **触发时机**：仅在会话结束（Session End）时运行一次。
  - **优势**：轻量级，不增加单次对话的延迟；能够评估整个会话的完整上下文，而非通过碎片化信息判断。
- **不使用 UserPromptSubmit**：
  - **缺点**：在每条消息发送时都会运行，开销大，延迟高，且对于“总结学习”这一目的来说是大材小用。

### 🛠️ 安装步骤 (Installation)

```Bash
# 方式 A：克隆完整仓库
git clone https://github.com/affaan-m/everything-claude-code.git ~/.claude/skills/everything-claude-code

# 方式 B：仅获取 continuous-learning skill (推荐)
mkdir -p ~/.claude/skills/continuous-learning
curl -sL https://raw.githubusercontent.com/affaan-m/everything-claude-code/main/skills/continuous-learning/evaluate-session.sh > ~/.claude/skills/continuous-learning/evaluate-session.sh
chmod +x ~/.claude/skills/continuous-learning/evaluate-session.sh
```

### ⚙️ 配置文件 ([**Hook Configuration**](https://github.com/affaan-m/everything-claude-code/blob/main/scripts/hooks))

将以下内容添加到你的配置文件中，用于在会话结束时触发评估脚本：

```json
{
  "hooks": {
    "Stop": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/skills/continuous-learning/evaluate-session.sh"
          }
        ]
      }
    ]
  }
}
```

### 📂 存储位置

提取出的模式（Patterns）将被保存为可复用的 skills，存放于：`~/.claude/skills/learned/`。

## 3. 使用模式

### 自动模式 (Automatic)

- 基于 `Stop` hook，脚本在会话结束时自动分析日志，提取错误解决方案或特定模式。

### 手动模式 (Manual Extraction)

- **命令**：`/learn`
- **场景**：当你刚解决了一个复杂问题，不想等到会话结束。
- **流程**：
  1. 输入 `/learn`。
  2. 系统提示提取当前模式。
  3. 起草 skill 文件。
  4. 用户确认后保存。

### 会话日志规范 (Session Log Pattern)

Skill 依赖于特定格式的会话日志文件：

- **路径**：`~/.claude/sessions/`
- **命名格式**：`YYYY-MM-DD-topic.tmp`
- **内容结构**：包含当前状态、已完成项、阻碍点 (Blockers)、关键决策和下一次会话的上下文。

## 4. 其他自我进化记忆模式 (Alternative Patterns)

除了上述方案，社区还有其他两种主流思路：

1. **反思日记 (The "Diary" Approach - @RLanceMartin)**
   - **机制**：利用“反思 Agent”在每场会话后分析日志。
   - **内容**：记录什么做得好、什么失败了、做出了哪些修正。
   - **结果**：更新一个“偏好/记忆文件”，在后续会话中预加载。
2. **主动建议 (Proactive Suggestions - @alexhillman)**
   - **机制**：系统不等待会话结束，而是每隔 15 分钟主动提出改进建议。
   - **流程**：Agent 审查近期交互 -> 提议更新记忆 -> 用户批准/拒绝。
   - **进化**：系统通过用户的批准模式来学习用户的偏好。
